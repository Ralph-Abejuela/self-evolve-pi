self-evolve-pi — how the harness works

A pi extension that keeps an LLM agent's context small without losing information, by borrowing five mechanisms from the self-evolving-agent-harness literature (SoL-Pi style). This page teaches each mechanism, where it hooks into pi, and what the measurements showed.

1 · The problem: context re-billing

Every agent turn re-sends the whole conversation to the model. A 20 KB shell log read at turn 2 is billed again at turn 3, 4, 5… An agentic task with 30 turns can pay for that log 30 times. The harness's job is to make the context small while keeping the information reachable.

Live illustration — one 2,560-token log, N turns, no harness:

Two escape hatches exist, and the literature ranks them: deterministic elision (a rule shrinks the text, provably keeping what matters) beats recoverable recall (keep a pointer, let the model page the data back), because recall turns re-bill context too. The extension implements both, elision first.

2 · Where it hooks into pi

pi fires lifecycle events. The extension registers handlers on five of them plus six custom tools. No model weights are touched — this is all runtime scaffolding (the "training-free" half of the paper).

pi.on("tool_result")        // every tool output passes through here
  ├─ reduceLog()            // shell logs → verified receipt   (mechanism 1)
  └─ pack()                 // >10 KiB output → L3 disk + excerpt (mechanism 2)

pi.on("context")            // fired when the window fills up
  └─ compact()              // archive old tool results → markers (mechanism 3)

pi.on("agent_before_settle") // the turn is about to end
  └─ fusion()               // edit landed unverified? chain one continuation (mechanism 4)

pi.on("before_agent_start")  // each agent run starts
  └─ guideline              // ~80 tokens teaching the BPE tool syntax

pi.registerTool() × 5       // harness_recall, harness_commit/track/note/state (mechanism 5)
pi.registerCommand("/evolve") // toggle mechanisms, read counters

State lives in .self-evolve/: config.json (toggles), the L3 archive (se://1, se://2… + index.jsonl), and per-run telemetry JSONL.

3 · The five mechanisms

3.1 — Evidence-preserving reducer elision

Shell output is mostly noise. A deterministic filter keeps the diagnostic lines (FAIL, ERROR, the summary: line) as a small receipt. The safety property: every quoted line is validated verbatim against the archived original — if the filter invents or mangles a line, the receipt is rejected and the full text is kept. The receipt also declares itself complete evidence, so the model doesn't page the archive "just to check" (an early version lost 32% of its savings to exactly that behavior).

3.2 — ObservationPack (L1 / L3 tiers + paged recall) recall

Any tool output over the threshold (2,560 tok ≈ 10 KiB, the paper's number) is written to the L3 disk archive. The context keeps only a head/tail excerpt and a handle (se://7). The model can read the full text back in pages with harness_recall(handle, page) — paying only for the pages it needs. read is excluded by default: packing a one-time intentional file read just adds recall turns (measured).

3.3 — Online context compact pressure

When estimated L1 tokens pass pressureTokens, old tool results (>400 tok, not from the current turn) are archived to L3 and replaced by one-line markers. Completed subgoals become compaction candidates — which is why the BPE harness_commit tool matters: committing a subtask marks its evidence as safe to shrink.

// on the "context" event, when estTokens > pressureTokens:
for old tool results (age > current turn, tokens > 400):
    handle = store.write("compacted", text)
    replace message text with
      `[compacted ${handle}: ${t} tok archived; harness_recall(handle, page) to recover]`

Honest note: this never fired in the test suite — pi's own shell tool already truncates big outputs and the reducer shrinks the rest, so no droppable candidates remained. It was verified working under forced conditions (5 × 1.9k inline results → compacted=2, saved≈3,770).

3.4 — Action fusion turn-boundary

The paper's fusion bundles an edit and its verification into one model request. An extension can't force the model to batch, but it can catch the failure mode at the turn boundary: if an edit/write landed and no pwsh/bash ran afterwards, agent_before_settle injects one bounded continuation (max 2 per run): "an edit landed without verification — run the check now." Zero extra user round-trips.

Turn timeline — click through a run where the model edits and stops:
tool_result edit → lastEditSeq = 1
assistant: "done, changed retries to 5" — turn wants to end…
agent_before_settle → guard: lastEditSeq=1, lastVerifySeq=-1 ⇒ FIRE
inject custom_message [action fusion] + continue: true — no user round-trip
tool_result pwsh (model verifies) → lastVerifySeq = 2 → settle clean ✔

3.5 — BPE slots: belief / progress / experience durable state

Four tiny tools keep structured state out of the context, persisted with pi.appendEntry (durable session entries):

ToolSlotWhat the model stores
harness_commitprogress"subtask X done" — also marks evidence compactable
harness_trackbeliefenvironment facts: paths, ports, versions
harness_noteexperiencereusable lessons ("the emitter must run from fixture cwd")
harness_stateread-backrecover all slots cheaply after compaction/resume

Because the model won't discover these tools unprompted, a ~80-token guideline is injected at before_agent_start — the training-free stand-in for the paper's SFT stage. It worked: 2–4 BPE calls per measured triage run.

4 · What was measured (and the trap found on the way)

The measurement trap. The first comparison used pi -ns -ne -nc (no skills / extensions / context) as baseline: a stripped pi with a 2.8k-token system floor. Any --extension run carries pi's ~23.4k global-extension floor. Result: a bogus −113.9% "reduction" that was pure environment asymmetry. Fair baseline = default pi -ns. Always give both arms the same floor.

Final methodology: independent A/B, both variants measured identically from their own session files (provider-reported input + cacheRead = context, summed per request), n=3 per cell, medians, two replication suites.

Reading: the harness pays a small fixed overhead (~1k: tool schemas + guideline) that shows on single-shot QA, and pays for itself ~2× on long agentic loops where the same big noisy output would be re-billed every turn — exactly the regime the paper targets. Evidence-preserving elision (reducer) drove the win; agent-behavior variance at n=3 is large, hence medians + replication.
